Privacy Policy

App: Hex · Developer/Owner: Obsidian Labs
Effective date: October 5, 2026 · Last updated: October 5, 2026

This Privacy Policy explains what Hex collects and stores when you use it on Discord, why that happens, who processes data for us, and how you can ask us to delete your stored Hex data.

We do not sell your personal data.

This policy describes Hex’s current v3.0 behavior. It is written to match how Hex actually works—not aspirational claims.

1. Who we are

Hex is owned and operated by Obsidian Labs. Contact for privacy and data-deletion requests: theobsidianlabs.dev@gmail.com.

2. What Hex is

Hex is a Discord bot that can chat, understand images and files you send it, create simple memes/GIFs from uploads using local image tools, remember optional facts, schedule messages, summarize channels (when permitted), and provide moderation assistance (such as forwarding user reports). Hex does not currently offer voice features or paid AI image generation.

3. Information Hex processes

Depending on how you use Hex, we may process:

  • Discord user IDs (to know who is chatting, whose memories belong to whom, rate limits, creator-only features)
  • Guild / server IDs (to scope server features and permissions)
  • Channel and message IDs (when needed for replies, summaries, reports, pins/reacts, schedules, or Actions)
  • Message content you send to Hex, including:
    • Direct messages to Hex
    • Mentions / slash commands directed at Hex
    • Messages in Hex’s designated home channel (#hex), where no mention is required
  • Conversation / thread state used to keep short-term context for ongoing chats
  • Personal memories you ask Hex to store about you (private to your user ID)
  • Server memories that admins/creators save for a guild (shared server context, separate from private memories)
  • Scheduled messages you ask Hex to send later
  • Moderation reports you submit (including the reported message link/content context Hex can fetch, your reason, and related IDs) so they can be delivered to a configured mod channel or to the creator via DM
  • Uploaded images and files when you ask Hex to analyze them, caption/meme/GIF them, or otherwise process them (subject to Hex’s size/type limits)
  • Basic operational metadata such as timestamps and configuration flags needed to run the bot (for example, whether a home channel ID is set)

Hex generally does not intentionally scrape or store every message in a server. Channel history is read when a feature needs it (for example, /summarize or soft channel context) and is bounded by message/character limits. Server members’ messages that are never directed at Hex are not treated as Hex “chat history” for memory.

4. Why we process this data

  • To provide Hex’s features (replies, memory, schedules, media tools, summaries, reports, Actions)
  • To keep private memories separate from other users
  • To enforce rate limits and creator/admin gates
  • To operate, debug, and maintain the service
  • To respond to privacy/deletion requests you send us

5. AI processing (OpenAI)

When Hex needs an AI reply or analysis, relevant content—such as your prompt, recent conversation context, memories Hex retrieves for that request, and images/files you asked it to analyze—may be sent to OpenAI for processing.

OpenAI processes that content under its own terms and policies. We use OpenAI as a processor to run Hex; we do not use Hex to sell your data.

6. Where data is stored

  • SQLite database on Hex’s hosting environment (Bot-Hosting.net), used for things like user threads, conversation state, personal memories, server memories, and scheduled messages
  • Production backups of that database, which may be created before updates/migrations or for operational recovery (for example, pre-deploy and pre-migration copies). Backups are operational copies; they are not a separate “product feature” for browsing your data
  • Host and Discord infrastructure logs may incidentally include operational messages while Hex runs

Images and files are processed for the request you make. Hex’s design aims to handle media in memory for analysis rather than building a long-term media library, but temporary files, caches, or host-level artifacts can exist during processing. Do not assume permanent encrypted storage of uploads.

7. Retention and deletion

Hex currently stores operational data in SQLite for as long as it remains in the production database (and any backups that still exist). Hex does not currently enforce automatic deletion after a fixed number of days for memories, conversation state, schedules, or reports.

You can remove some data yourself inside Discord using Hex’s commands/phrases where available (for example, forgetting personal memories). Server memories are managed by authorized users in that server.

To request deletion of your stored Hex data, email theobsidianlabs.dev@gmail.com from an account you can prove is tied to your Discord identity, and include:

  • Your Discord username and user ID
  • What you want deleted (for example: personal memories, conversation state, schedules associated with you)

We will work to delete or anonymize your personal Hex records from the live production database. Please note:

  • Some data may remain temporarily in existing backups until those backups are rotated or replaced
  • Server memories or reports that involve multiple people may be edited rather than fully erased if full deletion would break another user’s legitimate record
  • Content that only exists in Discord (not in Hex’s database) must be managed through Discord
  • OpenAI may retain data according to its own policies for the period they control

8. Sharing and third parties

We share data only as needed to run Hex:

  • Discord — the platform where Hex runs; message delivery and identity are governed by Discord
  • OpenAI — AI processing for prompts/context/media you ask Hex to handle
  • Bot-Hosting.net — hosting for the Hex process and its SQLite database

We may also disclose information if required by law, or to protect the rights, safety, and integrity of users, Hex, or Obsidian Labs.

We do not sell personal data.

9. Security practices

We take practical steps to protect Hex, including:

  • Keeping bot tokens and API keys in host environment configuration (not in public legal repos or public source)
  • Restricting creator-only and privileged Actions
  • Rate limiting to reduce abuse
  • Avoiding logging of secret values in Hex’s own application logs where redaction is implemented
  • Separating private user memories from shared server memories in prompts

No method of transmission or storage is perfectly secure. We do not claim that all Hex data is encrypted at rest on the host, or that deletion from every backup is instantaneous.

10. Children

Hex is intended for users who are allowed to use Discord under Discord’s own age rules. If you believe a minor’s data was stored in Hex contrary to those rules, contact us and we will review deletion.

11. Your choices

  • Don’t send Hex information you don’t want processed
  • Use forget/memory commands where available
  • Leave servers or stop DMing Hex if you no longer want to interact
  • Email us for a deletion request (Section 7)
  • Server admins can remove Hex from a server at any time

12. Changes to this policy

We may update this Privacy Policy as Hex changes. The “Last updated” date will change when we do. Continued use after an update means you acknowledge the revised policy.

13. Contact

Privacy questions and data-deletion requests: theobsidianlabs.dev@gmail.com
